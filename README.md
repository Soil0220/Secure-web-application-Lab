# Secure Web Application Lab - 정부 지원금 통합 신청 시스템
> **웹 모의해킹 취약점 진단 및 보고서 작성을 위해 자체 제작한 타겟 웹 애플리케이션**



## 프로젝트 개요

본 프로젝트는 정부지원금 서비스의 실제 운영 환경을 모의한 웹 애플리케이션을 직접 설계·개발하고, 
이를 대상으로 웹 모의해킹 및 취약점 진단 전 과정을 수행하는 것을 목적으로 제작한 보안 프로젝트입니다.

단순한 기능 구현에 그치지 않고, 실제 웹 서비스에서 발생할 수 있는 인증·인가, 세션 관리, 입력값 검증, 파일 처리, 
데이터 보호 등 다양한 보안 이슈를 고려하여 애플리케이션을 구성하였습니다.

또한 취약한 환경을 별도로 구성하여 시나리오 기반으로 취약점을 재현하고 공격 과정을 수행한 뒤, 취약점의 원인·영향도·대응 방안을 분석하고 
이후 실제 서비스에 적용할 수 있는 시큐어 코딩 및 보안 통제를 적용하였습니다.

최종적으로 각 취약점에 대한 취약점 분석, 위험도 평가, 침투테스트 과정(공격 자동화 스크립트 포함), 대응방안, 비지니스 영향, 이행점검 및 조치가이드를 
취약점 진단 보고서로 작성하여 웹 애플리케이션 개발부터 공격·분석·개선까지의 전 과정을 하나의 프로젝트로 구성하였습니다.

### 주요 보안 구현 사항

* CorsFilter를 적용하여 허용된 출처에서 발생한 요청에 대해서만 웹 브라우저가 응답을 읽을 수 있도록 CORS 정책 적용
* RequestTracingFilter를 적용하여 X-REQUEST-ID 중복 검증, X-REQUEST-TIME 시간차 검증 및 요청 추적·로그 기록
* SessionCheckFilter를 적용하여 세션 유효성 및 요청에 대한 접근 권한 검증
* DoubleSubmitCookieFilter를 적용하여 XSRF-TOKEN 헤더와 쿠키값의 일치 여부를 검증함으로써 CSRF 방지
* 로그인 시 세션 재생성을 적용하여 세션 고정(Session Fixation) 방지
* 세션 유효시간을 15분으로 설정하고 필요 시 연장할 수 있도록 하여 장시간 세션 유지에 따른 세션 탈취 위험 완화
* 타이밍 공격을 방지하기 위한 안전한 검증 함수 적용
* 안전한 일방향 해시 알고리즘을 이용한 패스워드 보호 및 안전한 양방향 암호화 알고리즘을 이용한 계좌정보 암호화
* 정보노출을 방지하기 위한 요청·응답 표준화, 공통 예외 처리 핸들러 및 에러코드 정의
* 침해사고 발생 시 피해 추적 및 감사 가능성을 고려한 데이터베이스 Soft Delete 적용
* 시나리오 기반 취약점에 대한 시큐어 코딩 및 보안 통제 적용
  (취약점별 상세 대응 내용은 취약점 진단 보고서에서 확인)


### 세부기능

#### Public (비회원/공통)

- Grant (지원금 제도)

    - 지원금 제도 조회: 등록된 지원금 제도 목록 검색, 세부 내용 조회


- Notice (공지사항)

    - 공지사항 조회: 시스템 안내 및 지원금 관련 공지사항 목록 및 상세 내용 조회


- Account (계정)

    - 회원가입: 신규 사용자 정보를 등록하여 서비스 이용 계정 생성

    - 로그인: 사용자 자격 증명을 검증하고 시스템 접근 권한(세션) 부여

- Session (세션)

  - 세션 인증 확인: 현재 클라이언트의 세션 유효성 및 로그인 상태 검증

#### User (일반 사용자)

- Application (지원금 신청)

    - 지원금 신청: 필요한 정보 작성 및 증빙 서류 제출을 통해 신청 등록

    - 신청 내역 조회: 본인이 신청한 지원금의 심사 진행 상태 및 상세 정보 조회

    - 신청 취소: 지원금 신청건에 대한 직접 철회


- Document (서류)

    - 서류 등록: 서류함에 지원금 신청시 필요한 증빙 서류 파일 업로드

    - 서류 조회: 본인이 업로드한 제출 서류 목록 확인

    - 서류 삭제: 잘못 업로드했거나 불필요한 서류 파일 삭제

    - 서류 다운로드: 보관중인 증빙 서류 파일 다운로드

    - 신청서 첨부 서류 다운로드 : 신청서에 첨부한 서류 파일 재 다운로드


- Favorite (즐겨찾기)

    - 지원금 즐겨찾기 등록: 관심 있는 지원금 제도를 개인 즐겨찾기 목록에 추가

    - 즐겨찾기 조회: 관심 지원금 목록 모아보기 및 모집 상태 확인

    - 즐겨찾기 삭제: 즐겨찾기 목록에서 특정 지원금 항목 제거


- Inquiry (1:1 문의)

    - 문의 등록: 지원금 신청 및 서비스 이용 관련 문의글 작성

    - 문의 조회: 본인이 작성한 문의글 목록 및 관리자의 답변 내용 확인

    - 문의 수정: 문의글 내용 보완 및 수정

    - 문의 삭제: 작성한 문의글 삭제 처리


- Account (계정)

    - 로그아웃: 현재 인증된 사용자 세션을 만료시키고 보안 접속 종료

    - 계정 조회: 로그인한 계정 정보 조회

    - 계좌 수정: 계정 정보로 등록된 계좌 정보 수정

- Session (세션)

    - 세션연장: 세션만료 시간 연장(최대 15분)

#### Admin (관리자)

- Application (신청 관리)

    - 지원금 신청 내역 전체 조회: 모든 지원금 제도 신청자의 신청 내역을 조회

    - 지원금 신청 상태 변경: 제출된 사용자 신청건에 대한 심사 진행 및 상태 변경


- Grant (지원금 제도 관리)

    - 지원금 제도 등록: 신규 지원금 사업 정보 작성

    - 지원금 제도 수정: 기존 지원금 사업의 상세 내용 변경

    - 지원금 제도 삭제: 불필요하거나 오등록된 지원금 제도 삭제 처리

    - 지원금 모집 상태 관리: 지원금 제도의 모집 상태 변경


- Inquiry (문의 관리)

    - 문의 전체 조회: 모든 사용자의 서비스 이용 관련 문의 조회
  
    - 문의 답변 등록: 사용자가 등록한 문의에 대한 공식 답변 작성 및 처리 완료 상태 변경


- Notice (공지사항 관리)

    - 공지사항 등록: 시스템 안내 및 지원금 관련 안내사항 작성

    - 공지사항 수정: 이미 게시된 공지사항 내용 보완 및 수정

    - 공지사항 삭제: 만료되거나 불필요한 공지사항 삭제 처리


- Account (회원 관리)

    - 사용자 계정 조회: 전체 회원 목록 검색 및 세부 정보 조회

    - 사용자 계정 삭제: 부적절한 이용자 등에 대한 관리자 권한의 계정 강제 삭제

    - 계정 권한 변경: 관리자 권한으로 특정 사용자 계정의 권한을 승격 또는 강등

- Monitoring (모니터링)
    
    - 로그 조회 : 로그 조회 및 검색시 결과 반환

## 시나리오
*본 애플리케이션에는 OWASP Top 10 취약점중 일부가 의도적으로 포함되어 있습니다.*

```text
  1. 정찰(Reconnaissance): 소스맵 미제거로 인한 프론트엔드 코드 노출 및 IDOR 취약점을 통한 관리자 계정 식별
  2. 정보 유출(Information Disclosure): 파일 업로드 및 Path Traversal 기반 다운로드를 연계하여 서버 내부 중요 파일(DEVNOTES.md) 탈취
  3. 권한 상승(Privilege Escalation): Stored XSS를 악용하여 관리자 세션을 탈취하고 일반 계정을 최고 관리자로 승격
  4. 데이터 탈취(Data Exfiltration): 관리자 권한으로 타 지원자의 민감 서류(주민등록초본 등) 무단 열람 및 다운로드
  5. 데이터베이스 침해(SQL Injection): 획득한 관리자 권한으로 접근 가능한 모니터링 API에서 SQLi를 수행하여 전체 DB 덤프
```
